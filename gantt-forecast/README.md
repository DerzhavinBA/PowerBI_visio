# Гантт ТМХИ 1.6.3.0 — прогноз завершения

Восстановленный сборочный проект на основе `Гантт_ТМХИ.pbiviz` 1.5.1.0. Исходный TypeScript-проект отсутствовал: `vendor/visual.js` содержит неизменённый JavaScript исходной сборки, новые функции находятся в `src/`. Это не полное восстановление оригинальных исходников.

Готовый пакет: [Гантт_ТМХИ_1.6.3.0.pbiviz](dist/Гантт_ТМХИ_1.6.3.0.pbiviz). GUID сохранён, API обновлён с 4.7.0 до 5.1.0. Сначала импортируйте **в копию отчёта**: пакет обновляет существующий визуал. Реальный импорт, fx, сохранение PBIX и Service в этой среде не проверены.

## Подключение в Power BI

1. Импортируйте пакет через меню визуализаций «Импортировать визуальный элемент из файла». Для существующего Гантта подтвердите обновление в копии отчёта.
2. Сохраните текущие назначения полей. «Дата окончания» — плановая дата.
3. Добавьте столбец типа **Дата** или **Дата/время** в новое поле **«Прогнозная дата завершения»**. Выбирайте само поле, не автоматическую иерархию даты.
4. Откройте «Формат визуального элемента → Прогноз завершения». По умолчанию включены серое продолжение с вертикальной штриховкой и конечный маркер. Подпись даты выключена. В списке **«Вид линии прогноза»** доступны вертикальная штриховка, сплошная заливка, диагональная штриховка, пунктирная и точечная линии. Пунктир и точки проходят по центру полосы; область клика остаётся на всю её высоту. Цвет вручную или через fx действует на все пять вариантов.
5. Для прямой привязки DAX перетащите меру с текстовым цветом `#RRGGBB` в новое необязательное поле **«Цвет прогноза (DAX)»**. Цвет применяется к линии и, по умолчанию, маркеру.
6. Другой способ: для формулы цвета нажмите **fx** рядом с цветом, выберите форматирование по значению поля и меру, возвращающую цвет. Проверка этого диалога в Power BI остаётся частью приёмки.

Поздний прогноз продолжает полосу от плана; ранний и совпавший отмечаются маркером. Отсутствие прогноза сохраняет старый вид. На свёрнутых группах прогноз не агрегируется. Прогноз раньше начала и неправильный тип поля дают сообщение, основная работа остаётся видимой.

В host-подсказке: начало, окончание план, окончание прогноз, отклонение в календарных днях. Положительное отклонение — позже плана. Продолжение и маркер выделяют исходную работу и передают её идентичность в контекстное меню. Цвет без результата формулы возвращается к постоянному цвету, по умолчанию `#808080`.

## Пример DAX

Создайте меру, заменив название таблицы и колонок своими:

```dax
Цвет прогноза =
VAR План = MAX ( 'Работы'[Дата окончания] )
VAR Прогноз = MAX ( 'Работы'[Прогнозная дата завершения] )
RETURN
    SWITCH (
        TRUE (),
        ISBLANK ( Прогноз ) || ISBLANK ( План ), BLANK (),
        Прогноз > План, "#D23100",
        Прогноз < План, "#176B34",
        "#808080"
    )
```

Перетащите эту меру в поле **«Цвет прогноза (DAX)»** или укажите её в fx цвета линии. Приоритет: корректное значение меры → корректный цвет fx → постоянный цвет. `BLANK()` или неправильный цвет из меры возвращает цвет fx/настроек. Мера вычисляется Power BI в контексте работы; формула не исполняется внутри визуала. Обеспечьте детализацию до одной работы: одно название в разных ветках допустимо, неоднозначные идентичности диагностируются. Исходный движок использует идентичность категории даты окончания; новый слой использует ту же идентичность, а не текст названия или индекс после сортировки.

Набор для ручной приёмки и пример рассчитанной таблицы: [example.dax](docs/example.dax).

## Толщина и маркер

В «Прогноз завершения → Оформление»:

- **Автоматическая толщина линии** включена по умолчанию и сохраняет прежний вид. Отключите её, чтобы задать **Толщину линии (пикс.)**: 1–64. Она применяется ко всем пяти стилям и ограничивается высотой основной полосы; продолжение центрируется относительно неё.
- **Автоматическая высота маркера** сохраняет прежнюю высоту. Отключите её, чтобы задать **Высоту маркера (пикс.)**: 4–96, с ограничением высотой строки.
- **Толщина маркера (пикс.)**: 1–16; исходное значение 2. Маркер остаётся центрированным точно на прогнозной дате.
- **Маркер — цвет линии** включён по умолчанию. Выключите, чтобы открыть отдельный **Цвет маркера** с fx/DAX. Эта настройка не меняет цвет основной полосы работы.

При малой толщине область клика продолжения сохраняется на всю высоту основной полосы. Высокий контраст хоста имеет приоритет над DAX/ручными цветами. Сброс карточки сбрасывает и скрытые размеры, и условные цвета.

## Настройки

Панель `getFormattingModel` группирует прежние свойства по разделам: шкала и календарь, работы, прогноз завершения, иерархия и порядок, подписи и столбцы, цвета и легенда, маркеры и вехи, взаимодействия, дополнительно. Условно скрытые параметры, списки категорий, селекторы уровней и диапазоны числовых настроек берутся из прежней логики. Расширенные параметры шкалы, масштаба и полос вынесены в группы «дополнительно». Имена сохраняемых объектов и свойств не менялись.

Встроенная панель фильтров не переписывалась. Высокий контраст для новых элементов использует палитру хоста; полная доступность исходного движка не заявляется.

## Сборка и проверка

Использованы Node 26.5.0, npm 11.17.0; версии зависимостей зафиксированы в lockfile.

```sh
npm ci --ignore-scripts
npm run baseline
npm test
npm run verify
```

`npm test` сначала собирает актуальный пакет, затем запускает тесты. Отдельная сборка: `npm run build`. Пакет создаёт официальный emitter `powerbi-visuals-webpack-plugin` из состава Power BI visuals tools; восстановленный JS подключается без повторной минификации. CLI `pbiviz package` не используется, потому что оригинального TS-проекта нет. Существующие пустой email автора и лицензионные уведомления сохранены; публикация в AppSource не выполнялась.

`baseline` воспроизводит все файлы внутри исходного архива побайтово; ZIP-метаданные нормализуются. `verify` проверяет хеш оригинала, неизменность старого кода/ролей/настроек, синтаксис и содержимое нового пакета. Сборка воспроизводима с одинаковым SHA-256 при неизменных входах.

Локальный браузерный стенд (имитация хоста, не Power BI):

```sh
npm run preview
python3 -m http.server 8766 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8766/docs/preview.html`. Шрифты/масштаб демо заданы только для стенда, а не как новые значения по умолчанию для старых отчётов.

## Границы проверки

- Результаты и ручной чек-лист: [acceptance.md](docs/acceptance.md).
- В исходном визуале нет свойства фиксированных начальной/конечной дат оси. Сохранены ручной масштаб по периоду, прокрутка и ограничение отрисовки текущей шкалой; новый редактор фиксированного диапазона не добавлялся.
- Даты используют календарь и часовой пояс окружения, как основной движок. Даты без времени при дневном масштабе заканчиваются в 23:59:59; при часовом масштабе сохраняется полночь. Значения с ненулевым временем сравниваются точно; отклонение в днях считается по календарным датам, без ошибки на переходе летнего времени. Часовой пояс бизнеса отдельно не вводился.
- Сохраняется исходный лимит выдачи 30 000 строк. Новая функция не добавляет сегментированную загрузку и не обещает полноту больших моделей.
- Сохраняются исходные механизмы лицензирования. Указанный исходной сборкой файл `visual.js.LICENSE.txt` отсутствовал; он не выдумывался и не заменялся.

## Вернуть стандартные настройки

В режиме редактирования отчёта внизу слева внутри визуала находится кнопка «Вернуть стандартные настройки». Она удаляет сохранённые параметры оформления через Power BI persistProperties, включая скрытые параметры прогноза и правила fx. Power BI применяет исходные значения при следующем обновлении. Привязки полей, лицензия и состояние сворачивания сохраняются. Подключённая мера «Цвет прогноза (DAX)» остаётся и продолжает определять цвета. В режиме чтения кнопка скрыта. Проверка сохранения и сброса в Desktop/Service обязательна; локальные тесты проверяют запрос к API хоста.
