# UX/UI для визуализаций ТМХИ

Рабочие правила. Профиль цветов и шрифтов находится только в [теме](../themes/tmhi-profile.md); доступность — в [отдельном стандарте](accessibility.md).

## Композиция

Иерархия: вопрос/название → период и фильтры → данные → вспомогательные действия. Заголовок объясняет показатель, а не только тип графика. Легенда нужна, если кодировка не объясняется непосредственно рядом с данными.

Использовать согласованные отступы и выравнивание текста/чисел. Начальная сетка для новых компонентов — 4/8/16 px, допускается корректировка по плотности. Не превращать это в обязательные размеры SDK. Шрифт проверять в реальном масштабе чтения; не решать нехватку места бесконечным уменьшением.

Сначала убирать второстепенный декор и сокращать частоту делений, затем включать обоснованную прокрутку. Горизонтальная прокрутка допустима для широких таблиц и шкал времени, если сохраняется контекст строки. Вычислять раскладку по viewport, а не по размеру страницы 1920×1080.

## Взаимодействия

До реализации описать действие и результат: клик выделяет объект, фильтрует отчёт или раскрывает ветку — не смешивать молча. Отдельно определить множественное выделение, снятие выделения и восстановление состояния.

Показывать применённые фильтры; сброс должен иметь понятную область действия. Закладки для открытия панели не должны случайно менять данные. Поповер закрывается доступным действием, после закрытия фокус возвращается инициатору. Не перехватывать клавиши хоста без необходимости.

Tooltip дополняет данные: полное название, точное значение, единица, даты и контекст. Важное действие или сообщение нельзя оставлять только на hover. Нативные host tooltips предпочтительны там, где подходят; [S12](../sources.md).

## Состояния

| Состояние | Что увидит пользователь |
|---|---|
| Поля не назначены | Короткая инструкция, какие роли добавить |
| После фильтра нет строк | «Нет данных при выбранных фильтрах», понятный путь изменения фильтра |
| Недопустимые данные | Что неверно и какие строки/поля затронуты, без раскрытия лишних данных |
| Данные ограничены | Явное сообщение о неполноте; не изображать точный общий итог |
| Малый размер | Упрощённые подписи / полезный минимум, без наложений и недоступных кнопок |
| Выделение | Различимый выбранный объект с сохранением контекста остальных |

Анимация служит пониманию перехода. По умолчанию не добавлять autoplay и декоративное движение; поддерживать reduced motion при наличии анимации. Для экспорта состояние должно оставаться понятным без интерактивности.

Обязательная проверка композиции: целевой, узкий и низкий viewport; длинное русское название; 0/1/много элементов; пользовательский размер шрифта; развёрнутая панель и длинная легенда. Результат фиксировать скриншотами только из реально отрисованной версии.
