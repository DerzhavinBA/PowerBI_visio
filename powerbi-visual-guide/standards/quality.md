# Производительность и контроль качества

## Измерения

Фиксировать версию пакета/хоста, оборудование, размер viewport, число строк и категорий, глубину иерархии и сценарий. Использовать одинаковые обезличенные наборы и одинаковые фильтры до/после изменения.

Измерять первый рендер, повторный update, фильтрацию, выделение, resize, сворачивание и прокрутку. Performance Analyzer помогает оценивать работу в отчёте; внутренние замеры разделяют подготовку данных, раскладку и отрисовку. Не смешивать DAX/query duration с собственным временем рендера. Для resize использовать дополнительную инструментализацию, если хостовый измеритель его не отражает ([S09](../sources.md)).

Рабочий протокол: один холодный запуск отдельно, пять повторов каждого прогретого сценария; записать все значения, медиану и максимум. Это исходный протокол комплекта, не норматив Microsoft. Бюджет времени/памяти согласовать под целевые данные до оптимизации; не объявлять произвольные 100 ms или 10 000 строк универсальной нормой.

Оптимизировать по профилю: избегать повторного измерения текста, лишних DOM-узлов, обработчиков на каждый update, неснятых таймеров и повторной нормализации неизменных данных. Проверять утечки после многократного открытия/закрытия и resize. Виртуализация, кеш и Canvas применяются, если решают измеренную проблему.

## Матрица проверок

| Уровень | Сценарии | Свидетельство |
|---|---|---|
| Данные | Нет dataViews, пустой набор, 1 строка, null, 0, отрицательные, дубли, неверные даты | Тесты преобразования и ожидаемые результаты |
| Семантика | Итоги, проценты, единицы, план/факт, разные даты и календарь | Сверка с контрольной таблицей |
| Геометрия | Узкий/низкий/целевой viewport, длинный русский текст, много категорий | Скриншоты фактического рендера |
| Host | Selection, clear, multi-select, фильтры, подсказки, bookmarks | Выполненные шаги и наблюдаемый результат |
| Сохранение | Save/reopen, reset, обновление старого пакета | Копия тестового PBIX и версии |
| Доступность | Клавиатура, фокус, high contrast, screen reader | Ручной протокол |
| Объём | Типичный, целевой максимум, превышение границы | Число входных/отображённых строк и сообщение об ограничении |
| Выпуск | Build, package, импорт, Desktop/Service по целевой среде | Логи и хеш пакета |

Тестировать существенную логику и регрессии; не создавать тесты, которые только повторяют реализацию. Для unit tests применимы host mocks и Power BI testutils; конкретный runner выбирать совместимый с проектом, пример Microsoft с Karma/Jasmine не делает их обязательными ([S17](../sources.md)).

## Вердикт

«Готово» означает прохождение согласованных критериев для указанной среды. Отчёт о проверке содержит выполненное, непройденное и непроверенное отдельно. Ошибки данных, потеря настроек, неверная идентичность строк и недоступное основное действие блокируют выпуск. Косметические замечания оцениваются по влиянию на чтение. Наличие package-файла не заменяет приёмку в Power BI.
