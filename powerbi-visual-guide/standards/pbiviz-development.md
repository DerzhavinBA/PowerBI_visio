# Разработка и совместимость .pbiviz

## Начало работы

Получить исходный проект, если задача — поддерживаемая доработка. Если есть только сборка, описать пределы анализа; не выдавать извлечённый JS за полный исходный проект. Проверить `pbiviz.json`, package manifest, lockfile, capabilities, настройки и лицензионные уведомления. Зафиксировать версии Node, TypeScript, tools и API, реально используемые проектом; универсальную «последнюю» версию в этот комплект не зашивать.

## Контракт и архитектура

Заполнить [контракт данных](../templates/data-contract.md). Сопоставить `dataRoles`, `dataViewMappings`, условия и `objects` с реальными входами хоста ([S05](../sources.md)). Роли искать по метаданным, не по номеру столбца. Устойчивую идентичность строки не заменять текстовой подписью или индексом после сортировки.

Разделять адаптер DataView, проверку/нормализацию, модель отображения, раскладку, рендеринг и взаимодействия. Бизнес-агрегации выполнять в семантической модели, если для переноса в визуал нет конкретной причины. Документировать любую дополнительную агрегацию.

`constructor` создаёт необходимые ресурсы; `update` учитывает данные, размер и стиль; `destroy` освобождает таймеры, события и наблюдателей. Метод `getFormattingModel` нужен выбранному современному пути форматирования ([S01–S02](../sources.md)). Не создавать бесконечные циклы `update` → запись настроек → `update`.

Выбор SVG / Canvas определяется измерениями и доступностью. Canvas требует отдельной доступной структуры и hit testing; SVG не гарантирует доступность автоматически. Виртуализация должна сохранять идентичности и возможность добраться до нужной строки.

## Host API и настройки

- Использовать SelectionIdBuilder и SelectionManager для выделений, сохранять идентичности после сортировки и фильтрации ([S03](../sources.md)). Проверять одиночное, множественное выделение, очистку и контекстное меню, если оно заявлено.
- Локальное скрытие строк, host selection, highlight и фильтрация — разные механизмы. Для фильтрации через host проверять декларацию filter и `applyJsonFilter`, корректную цель и снятие фильтра ([S04](../sources.md)). Не обещать фильтрацию отчёта по наличию панели в визуале.
- Поддержку highlight объявлять только вместе с обработкой соответствующих входных данных; точные интерфейсы сверять с используемой версией SDK.
- Настройки должны иметь тип, значение по умолчанию, диапазон и понятное название. Неверный JSON в расширенном поле даёт ошибку и безопасное восстановление, не падение рендера.
- Современная панель — API 5.1+ и `getFormattingModel`. Для имеющегося API 4.7.0 требуется миграция с проверкой сохранённых object/property, а не механическая замена метода ([S02](../sources.md)).
- Сохранять только необходимое пользовательское состояние; различать временное состояние UI и настройки отчёта. Повторное открытие, закладки и reset проверять в хосте.
- Формат чисел и дат связывать с locale и метаданными поля; имена UI — с локализацией. Проверять русскую локаль на установленном пакете: режим разработки имеет ограничения локализации ([S11](../sources.md)).

## Объём и корректность

Нельзя считать data reduction гарантией полноты. Для больших наборов заранее выбрать поддерживаемую стратегию: сокращение данных с явным уведомлением либо сегментированная загрузка. При использовании fetchMoreData проверить mapping, признак сегмента, отказ запроса и отсутствие дублей при добавлении ([S16](../sources.md)). Не загружать бесконечно при смене фильтра.

Строки из данных выводить как текст; HTML при необходимости санитизировать проверенным способом. Не использовать eval для настроек. Привилегии декларировать только под нужную функцию. `privileges: []` не является результатом аудита безопасности или доказательством сертификации.

## Сборка и выпуск

Сохранять GUID для совместимого обновления того же продукта; новый GUID — отдельная установка с отдельной проверкой привязок. Имена ролей и свойств — интерфейс совместимости с сохранёнными отчётами. Удаление/переименование требует миграции и регрессионного PBIX.

Использовать команды сборки и тестирования проекта; упаковку выполнять средствами Power BI visuals tools ([S10](../sources.md)). Проверять созданный пакет: метаданные, иконку, версию, уведомления, размер и импорт в копию отчёта. Сборка сама по себе не подтверждает работу в Desktop/Service. Публикация и сертификация — отдельные задачи, их успех не следует из локальной упаковки.
