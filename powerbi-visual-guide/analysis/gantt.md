# Разбор «Гантт_ТМХИ»

## Подтверждённые сведения

Источник: `Гантт_ТМХИ.pbiviz`, ZIP-записи `package.json` и `resources/ganttTMHI.pbiviz.json`. Машиночитаемые доказательства: [метаданные и поиск по коду](evidence/gantt-summary.json), [capabilities целиком](evidence/gantt-capabilities.json), [инвентарь и SHA-256](evidence/inventory.json).

- Версия визуала 1.5.1.0; API 4.7.0; класс `GanttTMHI`; GUID `ganttTMHI84F997DD65FE42E9AAE536431246AB90`. Это сборка, а не исходный TypeScript-проект.
- 17 ролей данных; categorical mapping; `groups` допускает до двух полей, `items` и `levelSortKeys` — до пяти. `panelFilterFields` не имеет явного максимума в conditions. Это не доказательство неограниченной поддержки.
- `dataReductionAlgorithm.top.count = 30000`: нельзя обещать полноту больших наборов только по этому значению. В буквальном поиске JS `fetchMoreData` не найден.
- Объявлены обычные и canvas-подсказки, landing page и `supportsKeyboardFocus`. `privileges: []`, пользовательская сортировка. Объявления не равны пройденным функциональным тестам.
- JS содержит `createSelectionManager`, `tooltipService`, `persistProperties`, `enumerateObjectInstances`, обработчики `keydown`. Поиск `getFormattingModel`, `applyJsonFilter`, `isHighContrast` совпадений не дал. Отсутствие строки в сборке — сигнал для проверки, не доказательство отсутствия поведения.
- В поставке `stringResources` пуст, хотя названия ролей и настроек русские. Русский UI не доказывает полноценную локализацию по языку хоста.

## Контракт данных

| Роли | Подтверждённое назначение из displayName / conditions |
|---|---|
| groups, items, labels | Проект и подгруппа; уровни строк; название работы |
| froms, tos | Дата начала и окончания, максимум по одному полю |
| categories, objTypes, descriptions | Категория, тип элемента, описание |
| values, measures | Значение (Grouping) и дополнительный столбец (Measure) — не смешивать |
| sorting, levelSortKeys | Сортировка и ключи сортировки уровней |
| currentStateOffset / Color | Смещение текущего состояния в днях и цвет |
| hierarchyMarkerOffset / Color | Смещение маркера уровня и цвет |
| panelFilterFields | Поля панели фильтров |

Не выводить из названия роли точную семантику данных. Для доработки отдельно подтвердить значения `objTypes`, формулу смещения относительно даты, часовой пояс, объединение строк и агрегацию measures.

## Настройки и полезные решения

В capabilities 29 объектов настроек. Есть `zooming`, `xAxeFormat`, `tmhiCalendar`, `todayLine`, `targetLine`, `milestones`, `leftAxis`, `groups`, `subgroups`, `legend`, `wrapping`, `categoryMap`, `tmhiPanel`, `tmhiCurrent`, `tmhiLevel`, `tmhiSort` и другие.

**Повторно использовать как подход:** отделять настройки календаря от данных, давать явную сортировку и управляемые уровни иерархии; поддерживать отдельные маркеры и вехи; согласовывать легенду и категории. Для длинных шкал проверять плотность подписей на каждом масштабе. Это рекомендации на основе состава возможностей, а не визуальная оценка готового результата.

**Предложения для следующей доработки:** проверить доступность всех элементов панели, высокий контраст и полноту данных; отделить локальное скрытие строк от фильтрации отчёта; сократить сложность настроек прогрессивным раскрытием. В некоторых объектах десятки свойств, например `groupColors` — 124: это риск сложности, но не доказанная UX-ошибка.

## Наблюдения по коду доработок

В [извлечённых фрагментах](evidence/gantt-code-excerpts.json) видны три конкретных решения:

- Таймер с интервалом 60 000 ms сравнивает `new Date().toDateString()` с предыдущим днём и вызывает обновление при смене дня. Обёртка destroy снимает этот таймер и удаляет связанные элементы. Это положительный образец управления жизненным циклом; календарный день здесь берётся из окружения JavaScript, а не из явно заданного часового пояса бизнеса. Проверить смену суток и длительно открытую страницу.
- Панель формирует копию DataView с `categorical: result.data` и передаёт её исходному рендеру. Это свидетельство локального ограничения отображения в данном участке кода, а не фильтрации остальных визуалов Power BI. Отдельный путь `tmhiApplyConfig` проверяет режим редактирования и сохраняет config через host. Разделять временное состояние читателя и авторские настройки; проверить оба режима.
- `updateCount` добавляет число активных ограничений в заголовок «Видимость и фильтры». При render сохраняются раскрытые разделы, фокус и позиция прокрутки; есть кнопка «Сбросить». Эти решения стоит сохранять при переработке панели, проверяя восстановление фокуса на практике.

Дополнительно capabilities явно разделяет настройку масштаба по высоте строки и по периоду времени; для вех есть поведение на свёрнутых уровнях, пересечение подписей и форма; для маркера уровня — агрегация смещения и округление до дня. Эти настройки требуют самостоятельных сценариев, а не одного теста «Гантт открылся».

## Совместимость и происхождение

API 4.7.0 и наличие `enumerateObjectInstances` требуют отдельного плана перехода на современную панель форматирования: она использует API 5.1+ ([S02](../sources.md)). Простая замена номера API недостаточна. Сохранять имена ролей, object/property и идентичность визуала при совместимом обновлении; новый GUID означает отдельный визуал, который нужно привязать в отчёте.

[Оригинальное уведомление](evidence/THIRD-PARTY-NOTICES.original.txt) указывает ADWISE Gantt / Roadmap 3.1.3.0 и Державина Б.А. как автора доработок. Уведомление начинается с версии 1.1.0.0, а пакет — 1.5.1.0: метаданные требуют согласования при следующем выпуске. Уведомление сообщает об отсутствующем `visual.js.LICENSE.txt`; в текущем архиве такого файла также нет. Не выдумывать лицензию и не представлять эту сборку официальным релизом ADWISE. Перед распространением получить полные условия у правообладателя; механизмы лицензирования не обходить.

## Регрессии для будущих изменений

Проверить пять уровней, одинаковые названия в разных ветках, сворачивание и сортировку, однотипные даты и вехи, смену дня, плотные подписи, пустые входные данные, восстановление настроек после открытия PBIX. Проверить 29 999, 30 000 и 30 001 входных строк на полноту и явное сообщение об ограничении. Эти проверки пока не выполнялись в Power BI.
