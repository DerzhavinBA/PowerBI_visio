# Проектирование визуала Power BI

Внутренний локальный скилл. Использовать весь комплект вместе; глобальных инструментов не требует. Для исследования актуальных возможностей нужен доступ к официальной документации; без него явно отмечать непроверенные версии.

1. Изучить задание и имеющиеся файлы. Заполнить [brief](../../templates/visual-brief.md) и [контракт](../../templates/data-contract.md); неизвестные бизнес-правила не выдумывать.
2. Выбрать представление по [аналитическим правилам](../../standards/chart-design.md), затем описать раскладку и поведение по [UX/UI](../../standards/ux-ui.md).
3. Применить [профиль ТМХИ](../../themes/tmhi-profile.md) по умолчанию. Для темы пользователя сохранить его намерение и проверить контраст заново.
4. Прочитать [доступность](../../standards/accessibility.md). Спроектировать пустое состояние, ограничение данных и основной сценарий без мыши.
5. При доработке Гантта прочитать [его анализ](../../analysis/gantt.md); при интеграции в исходный отчёт — [анализ отчёта](../../analysis/report.md). Не переносить исторические ограничения на каждый новый визуал.
6. Перед выдачей перечитать применённые правила и проверить выбранный дизайн по [приёмке](../../templates/acceptance.md). Если хост недоступен, результат — спецификация, а не проверенный визуал.

Выход: заполненное задание, контракт данных и описание состояний/взаимодействий с критериями проверки. Код и публикация не подразумеваются. Для реализации передать материалы скиллу [разработки](../powerbi-pbiviz-development/SKILL.md).
