# Проверка визуализации

Внутренний локальный скилл. Файлы нужны для статического анализа, исходники — для проверки логики, Power BI host — для поведения и производительности. Проверять доступность каждой среды, не подразумевать её.

1. Зафиксировать пакет, версию, хеш, API и критерии задачи. Выяснить, какой GUID реально используется в тестовом отчёте.
2. Проверить данные по контракту и [правилам графиков](../../standards/chart-design.md); UI — по [UX/UI](../../standards/ux-ui.md) и [профилю](../../themes/tmhi-profile.md).
3. Отдельно проверить [доступность](../../standards/accessibility.md) и [качество/скорость](../../standards/quality.md). Для SDK-совместимости читать соответствующие части [стандарта разработки](../../standards/pbiviz-development.md).
4. Для каждой находки указать наблюдение, источник/шаг воспроизведения, эффект для пользователя и предлагаемое исправление. Ненайденная строка в минифицированном JS не доказывает отсутствие функции.
5. Перед выдачей перечитать применённые правила, заполнить [приёмку](../../templates/acceptance.md) и разделить «пройдено», «ошибка», «не проверено». Не заменять функциональные результаты списком возможностей capabilities.

Выход: приоритетный список находок и вердикт для конкретной среды. При статическом анализе можно принять качество документации/структуры, но нельзя подтвердить работоспособность визуала. Исправления выполняются только в пределах задачи; аудит сам по себе не разрешает публикацию.
