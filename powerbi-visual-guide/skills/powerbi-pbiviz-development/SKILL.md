# Разработка .pbiviz

Внутренний локальный скилл. Для сборки нужны исходный проект и совместимые Node/Power BI visuals tools; для приёмки — целевой Power BI host. Наличие ZIP-сборки не заменяет исходный проект.

1. Прочитать задание, контракт и [стандарт разработки](../../standards/pbiviz-development.md). Проверить имеющиеся версии и инструкции проекта; не обновлять зависимости без причины.
2. Для изменений Гантта прочитать [анализ](../../analysis/gantt.md), особенно GUID, роли, старую панель форматирования и происхождение. Определить совместимость до изменения интерфейса.
3. Реализовать необходимые преобразования, раскладку, host-интеракции и настройки. Читать [UX/UI](../../standards/ux-ui.md), [доступность](../../standards/accessibility.md) и [профиль](../../themes/tmhi-profile.md) для затронутых частей.
4. Проверять логику и регрессии по [качеству](../../standards/quality.md). Для новых API сверяться с [источниками](../../sources.md) и фактическими типами проекта.
5. Упаковать разрешённые изменения, проверить импорт и сохранение в копии отчёта, когда host доступен. Сохранить оригиналы и лицензионные уведомления.
6. Перед выдачей перечитать применённые стандарты и заполнить [приёмку](../../templates/acceptance.md). Передать на [проверку](../powerbi-visual-review/SKILL.md).

Выход: изменения, пакет при доступной сборке, результаты проверок и конкретные ограничения. Если исходников/host нет, указать, какая часть не выполнена; не подменять её заявлением об успешном выпуске. Публикация не входит автоматически в разработку.
